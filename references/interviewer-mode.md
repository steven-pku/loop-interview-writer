# Interviewer 模式（面试官侧 / 出题验简历）

> 与候选人侧反向：这里用户是面试官，目标是**设计一场验证候选人简历的面试**，不是帮候选人准备答案。
> 触发：招聘方/面试官说「帮我设计面试题/怎么面这个人/怎么验证这份简历/该问什么」。
> 上游接口：直接消费 loop-resume-writer 的 Resume Audit 追问清单（若有）——Audit 判「该验什么」，本模式出「怎么问、怎么判答案」。跨 skill 闭环。
> 边界：给结构化面试设计与答案判读框架，不替代录用决策；不教诱导性/歧视性问题。

## 与候选人侧的反向对应

| 候选人侧（主流程） | 面试官侧（本模式） |
|---|---|
| 从账本准备答案 | 从简历声称设计追问 |
| Mock pass：预演可能被追问的点 | 同一套 M1-M5 追问模式，但**面试官来问** |
| 目标：答得住 | 目标：判断答得住 vs 答不住（真实 vs 注水） |

## 工作流

### 1. 输入归集
- 有 Resume Audit 报告/追问清单 → 直接用其 🚩 项作为验证靶点（推荐：先跑 loop-resume-writer 的 Audit）。
- 只有简历 → 现场把简历声称分两类：可核实（教育/证书/任职时间线，面试或背调可查）vs 需举证（量化成果/角色定位/技能熟练度自评，只有候选人本人能证）。挑「需举证 × 岗位核心」的高风险声称作验证靶点。

### 2. 验证靶点排序
按「风险 × 岗位关键度」排：既是简历核心卖点、又最难核实的声称优先（如「主导千万级项目」的真实角色）。

### 3. 出题（复用 M1-M5 追问模式，面试官视角）
每个靶点配一道主问 + 2-3 层追问阶梯（见 `references/mock-followup-guide.md` 的 M1 数字深挖 / M2 角色边界 / M3 反事实 / M4 失败探底 / M5 压力质疑）。面试官侧关注：追问到第几层开始露怯。

### 4. 答案判读框架（本模式独有）
每道题给三档参照，让非专业面试官也能判：
- **可信答案长这样**：能给出具体机制/数字来历/角色边界，追问越深越具体。
- **注水信号**：越追越模糊、换主语（我们/团队）、把结果归于外部、数字说不出来历。
- **危险信号**：与简历自相矛盾、临时改口、对本该熟悉的细节答不上。

### 5. 产出面试计划（模板见下）

## 面试计划模板

```markdown
## 验证面试计划 · {候选人代号} · 目标岗位 {岗位}
（上游：Resume Audit {有/无} · 时长建议 {N} 分钟）

> 时长-题量粗配比：45 分钟 ≈ 3-4 个验证靶点 + 2 能力探针 + 开场/反问；30 分钟砍到 2 靶点。

### 开场（3-5 分钟）
- 破冰 + 让候选人自述最近一段核心经历（听 vs 简历是否一致）

### 验证问题（按优先级）
1. 【靶点：{简历声称}】
   - 主问：「{问题}」
   - 追问阶梯：L1{…} → L2{…} → L3{…}（M{n} 型）
   - 可信答案 / 注水信号 / 危险信号：{三档}
2. …

### 能力探针（岗位硬技能，非简历验证）
- {岗位关键能力} → 情境题/作品追问

### 🚩 红旗观察清单
- {Audit 标出的必澄清项，逐条列，面试中必须问到}

### 判读小结（面试后填）
- 验证通过的声称：
- 未通过/存疑：
- 综合建议：
```

## 纪律

- 只验证简历声称与岗位能力，不问与岗位无关的隐私/歧视性问题（婚育/户籍歧视/年龄等）。
- 追问是为核实不是为刁难；M5 压力质疑用于观察稳定性，不是羞辱。
- 面试官侧不承诺「测谎」，只提供「哪些答案模式值得警惕」的结构化参照，最终判断在面试官。
