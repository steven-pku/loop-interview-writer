# Mock 追问模式库

> Mock pass 用法：对每个已过 QA 的答案，按下列模式追问 2-3 层。答不住的洞 → 转具体修订规则回 QA loop，或缺数据 → 进追问清单。Mock QA 模式（用户贴答案）同样用本库。

## 五类追问模式

### M1 数字深挖
- L1「这个 X% 是怎么统计出来的？」→ L2「基线是什么时候的数据？」→ L3「排除了别的因素吗（大盘涨/换季）？」
- 测试点：账本来源标注是否真扛得住。「合理推算」类数字必须能当场说出推算式。

### M2 角色边界
- L1「这个项目团队几个人？」→ L2「里面你具体负责哪块？」→ L3「如果把你换掉，结果会差在哪？」
- 测试点：A 是否被夸大。答案措辞强度不得超过账本角色记录。

### M3 反事实
- L1「如果重来一次，你会改哪个决定？」→ L2「当时为什么没这么做？」
- 测试点：复盘深度。答不出改进点＝故事只背了没想过。

### M4 失败探底
- L1「这个失败最大的代价是什么？」→ L2「你的责任占几成？」→ L3「之后哪件事证明你真的改了？」
- 测试点：失败故事的真实性与改变的可验证性。

### M5 压力质疑
- L1「说实话，这个结果我觉得一般。」（不提问，只否定）
- 测试点：情绪稳定 + 能否补充语境而不辩解、不缩水立场。参考应对结构：接住（「从 X 标准看确实有差距」）→ 补语境（当时约束）→ 亮底线（在该约束下这个结果意味着什么）。

## 追问后的处理分流

| Mock 结果 | 动作 |
|---|---|
| 答案有洞但账本有料 | 生成具体修订规则 → 回 QA loop |
| 洞在数据缺失 | 进追问清单，答案标〔待补数据〕降级表述 |
| 洞在事实本身（经不起 M2）| 措辞降级（「主导」→「负责其中 X」），或整个故事换角度 |
| 三层全接住 | 标记「追问预案」进故事卡 |
