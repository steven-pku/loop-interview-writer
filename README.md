## Job Kit 双仓协作

姊妹候选为 `loop-resume-writer`，计划与本仓同步提供公开审查；此处不假设其远端已存在。两个仓各自内置 `references/career-facts-ledger.md`，本次两份文件逐字一致，可独立阅读，无需在另一仓取运行文件。

协作方式是由使用者保存并显式导入同一份账本；没有自动同步服务。共享 schema 与静态契约已对齐；字节一致仍不能证明实际行为，双件联动待新测试。联合审查请固定两个公开候选的提交，避免混用移动分支。

薪资临场 holding 可在本仓独立准备；offer 议价超出范围。相关 [loop-negotiation 固定公开候选](https://github.com/steven-pku/loop-negotiation/tree/383096ca0b0c201315814ded67ca22224be8c1f9) 仍为 HOLD，不是已验收依赖，也不要求安装后才能使用本仓。

## 证据与使用边界

本次导出不含真实简历、真实经历记录、试用日志或历史私有评审。静态导出只核对文件、来源差异、脱敏和本地引用，不验证评分正确、反编造表现、招聘公平性或安装成功。

仅用合成或充分脱敏材料做评审。不要上传身份、联系方式、精确薪资或可识别他人的履历。模型宿主和服务商可能保留输入或生成文件。来源标签不能验证用户提供事实的真伪；评分不能代替录用判断，也不预测面试或求职结果。指令要求和静态检查均不是对模型行为的保证。
